# ILA 3-1: Applying the Four Pillars of OOP

## Sari-Sari Store Inventory System

### 1. Encapsulation
Encapsulation can be used by creating a Product class that contains the product name, price, and stock quantity together with methods that manage them. The properties name, price, and quantity can be kept private, while public methods such as addStock(), removeStock(), getPrice(), and getQuantity() control how that data is accessed and changed. This means other parts of the program cannot directly modify the stock or price  they have to go through these methods, which can include checks (for example, preventing the quantity from going below zero). This keeps the product's data protected and prevents other parts of the program from changing it incorrectly. It also makes the inventory system more organized because the data and the methods that operate on it are grouped together.

### 2. Abstraction
Abstraction can be applied by hiding the complicated details of inventory operations and showing only the functions that the store needs to use. While encapsulation focuses on protecting the product's data, abstraction focuses on simplifying how the store owner interacts with it. For example, a sellProduct() method can internally check the stock, validate the sale, and reduce the quantity — but the store owner just calls sellProduct() without needing to know any of those steps happen underneath. The store owner only needs to interact with simple operations such as adding products, selling products, and checking stock. This makes the program easier to understand and use, especially for someone without a programming background.

### 3. Inheritance
Inheritance can be used when different types of products share common properties and behaviors. A general Product class could contain properties such as name, price, and quantity, while classes such as FoodProduct and DrinkProduct can inherit these properties from Product. The child classes can also have their own additional properties when needed — for example, FoodProduct could add an expirationDate property to track spoilage, while DrinkProduct could add a volume property (e.g., in milliliters) since drinks are often sold by size. This reduces repeated code and makes it easier to add new types of products to the inventory system without rewriting the shared properties each time.
### 4. Polymorphism
Polymorphism allows different product classes to use the same method name while performing the method differently. For example, a getProductInfo() method could be defined in the Product class and overridden by FoodProduct to also display the expiration date, or by DrinkProduct to also display the volume. The inventory system can call getProductInfo() on any product — food, drink, or otherwise — without needing to know which specific type it is dealing with; each object automatically displays the details relevant to its own type. This makes the program more flexible and easier to expand as new product categories are added.
## Reflection
Among the four pillars of Object-Oriented Programming, I think encapsulation would be the most useful for improving the sari-sari store inventory system. It keeps important information such as the price and stock quantity protected and allows them to be changed only through controlled methods, rather than being edited directly from anywhere in the program — this helps prevent incorrect changes, such as accidentally setting a negative stock quantity. While inheritance and polymorphism become more valuable as the store's product variety grows, a small sari-sari store may not need multiple product subtypes right away, whereas encapsulation is useful from the very beginning since even a single Product class benefits from having its data protected. This makes encapsulation the most practical starting point, and it becomes even more important as the number of products increases, since well-protected data is easier to maintain, debug, and expand safely over time.
